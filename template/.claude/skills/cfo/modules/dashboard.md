# Модуль: дашборд (dashboard)

Цель: владелец видит свои деньги наглядно, одним экраном. Только локальный файл `plan/dashboard.html`: никаких артефактов, облаков и внешних скриптов.

## Как устроен

- Генератор `tools/build_dashboard.py`, только стандартная библиотека python (csv, json, datetime, html, pathlib). Если его ещё нет, напиши по этому описанию. Читает то, что есть: `ledger/transactions.csv`, `plan/cash-plan.md`, `plan/net-worth.csv`, `plan/weekly/*.md`, `tax/<год>/checklist.md`, данные подписок. Чего нет, тот блок показывает «нет данных», а не выдуманные цифры.
- Пишет `plan/dashboard.html`. Данные встраиваются при сборке. Графики inline SVG, стили inline. Ни одного внешнего ресурса: ни шрифтов из интернета, ни CDN, ни картинок по ссылке. Открытый файл ничего не грузит из сети.
- Стиль спокойный: карточки, кольца прогресса, системные шрифты, светлая и тёмная тема по настройке системы.
- Суммы в целых долларах, счета только последними 4 цифрами.
- Открывает владелец сам: двойной клик по `plan/dashboard.html`. Агент файл никуда не отправляет.

## Блоки

1. Шапка: цель из `context.md`, дней до срока цели, разрыв в месяц сейчас, запас в месяцах.
2. Кольца: срезы сделаны на $X из $Y в месяц; доход пришёл $A из $B по плану месяца.
3. Доход и расход по месяцам: столбики, линия нетто.
4. Куда уходит: топ-8 категорий за последний полный месяц.
5. Подписки: всего в месяц, по решениям, ближайшие продления.
6. 8 недель: план и факт по неделям.
7. Чистые активы: ликвидные деньги и долги.
8. Налоги: дней до срока подачи, чек-лист документов «есть / нет».
9. Кредит: загрузка карт (когда отработал `credit.md`).

Внизу: дата сборки и список файлов, из которых собрано.

## Когда пересобирать

В конце `intake`, `weekly-check`, `monthly-review` и по просьбе владельца.

## Проверка после сборки

- `grep -c "https\?://" plan/dashboard.html` должен дать 0.
- Узкое окно (около 400px) не ломает вёрстку.
